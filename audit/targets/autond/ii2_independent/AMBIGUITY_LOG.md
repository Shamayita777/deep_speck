## Algorithm ambiguities

### A-001 — Mutation operator in L13
- **Paper says:** child = pop_i ⊕ pop_j ⊕ (m ? RandomInt(0, n−1)), where the
  operator glyph is missing in my rendering. §5.2 calls this mutation.
- **Choice:** left shift (m ≪ p). With m ∈ {0,1} and p ∈ [0, n−1], this flips
  one uniformly chosen bit, which is the standard single-bit mutation and uses
  exactly the range of valid bit positions.
- **Alternative:** multiplication, m·p. That would XOR in a small integer
  (≤ n−1), touching only the low ~log₂n bits. That does not fit "mutation"
  over an n-bit space.
- **Impact:** High if wrong. Low confidence it is wrong.

### A-001 — addendum (revised)
The auditor's report that Gohr's operator renders as a shift came from the
same automated-extraction call that returned the fabricated A-017 sentence
(the auditor confirms it was one call, not merely the same tool), so it is
unverified. A-001 rests on my original reasoning alone.

### A-002 — Loop bounds (L4, L6, L7)
- **Paper says:** "for iterations ← 0 to 50", "for i ← 0 to 32",
  "for j ← i+1 to 32".
- **Open:** whether the bounds are inclusive.
- **Choice:** exclusive, giving 50 generations and indices 0..31.
- **Evidence:** §8 counts Σ_{k=1}^{31} k = 496 per generation over 50
  generations (24,800). Index 32 does not exist in a 32-member population.
- **Alternative:** inclusive, giving 51 generations.
- **Impact:** Low.

### A-003 — Random primitive conventions
- **Paper says:** RandomInt(0, 2^n−1) and RandomInt(0, n−1); RandomFloat(0, 1).
- **Choice:** RandomInt bounds are inclusive at both ends, since the upper
  bounds are exactly the maximum valid values. RandomFloat is [0, 1), so M = 1
  always mutates. The bit position is drawn even when m = 0, as the expression
  in L13 is evaluated either way.
- **Alternative:** skip the draw when m = 0. This changes only RNG consumption,
  not the distribution.
- **Impact:** Low (determinism bookkeeping only).

### A-003 — addendum
Per generation, all u values are drawn first, then all bit positions p, rather
than interleaving them per pair. The distribution is the same; only the RNG
consumption order differs.

### A-004 — The zero difference
- **Paper:** silent. Its sources:
  - L1 (probability ≈ 1024/2^n);
  - L13 with m = 0 when two population members are equal;
  - L13 with m = 1 when two members differ in exactly the mutated bit. This
    becomes likely as the population converges.
- **Why it matters:** b̃(0) = 0.5, the maximum. Zero would take over the
  population, and the outer loop's threshold stop could never fire. That would
  contradict §5.2's description of terminating at round R+1.
- **Choice:** discard zero wherever it is generated. It is not scored or
  counted.
- **Alternatives:** resample a replacement, which keeps exact counts of 1024
  and 496; or assign it a score of 0.
- **Impact:** High for small n and late generations.

### A-005 — Duplicate candidates
- **Paper:** silent on duplicates within a generation.
- **Problem:** without deduplication, the top 32 can be many copies of one
  difference. XORs of copies give zero (A-004) or single-bit differences, and
  the population collapses.
- **Choice:** deduplicate before scoring, keeping first occurrence; switchable
  via `deduplicate`.
- **Basis:** the paper treats returned lists as sets ("the union of these
  lists"), and Table 3 counts distinct "differences returned".
- **Alternative:** no deduplication.
- **Impact:** High on search dynamics. II-4 can run both settings.

### A-006 — Elitism
- **Paper says:** L17 replaces the population with the top 32 *candidates*.
  Parents are not carried over. §5.2 prose: "allowing the best ones to move to
  the next generation", which could also mean best of parents plus children.
- **Choice:** follow the pseudocode (no elitism); switchable via `elitism`.
- **Alternative:** (μ+λ) selection.
- **Impact:** Medium. Without elitism, the best difference found so far can be
  lost before the run ends.

### A-006 — addendum
Elitism, when enabled:
- The selection pool is the children followed by the parents.
- Parents keep their existing scores and are not rescored.
- With `deduplicate=True`, a child equal to a parent is dropped before scoring.
- The default remains no elitism, per L17.

### A-007 — What Algorithm 1 returns
- **Paper says:** L19 returns `candidates` (up to 496 values). §5.2 says
  "obtaining R lists of 32 differences".
- **Choice:** return the top 32 of the final sorted candidates, which equals
  the final population, with their final-sort scores. The full list is
  recorded under `per_round`.
- **Alternative:** return all candidates.
- **Impact:** High on union size and any Table-3-style count. Low on the
  top-ranked difference.

### A-008 — Where the threshold stop applies
- **Paper says:** §5.2: "The algorithm stops if no input difference scores
  higher than a threshold T_b." But Algorithm 1 has a fixed loop and no such
  test. The next paragraph applies T_b to the iteration over rounds.
- **Choice:** the threshold applies only to the outer round loop.
- **Alternative:** also stop Algorithm 1's generations early when no candidate
  exceeds T_b.
- **Impact:** Low on returned differences. Medium on evaluation counts.

### A-009 — Details of the threshold test
- **Paper:** silent on which scores are compared and how. It says only
  "no bias score above the threshold T_b is returned".
- **Choice:** the maximum of the scores returned in Δ_r, taken from the final
  generation's sort, compared with strict >.
- **Alternatives:**
  - use rescored values;
  - use any candidate in any generation;
  - use ≥.
- **Impact:** Low to Medium. It can shift R by one when scores sit near T_b.

### A-010 — Members of Δ_r scoring at or below T_b
- **Paper:** silent.
- **Choice:** keep all 32, following "lists of 32 differences".
- **Alternative:** keep only members above T_b.
- **Impact:** Medium on union size. Low on top ranks.

### A-011 — Round cap — NOT IN PAPER
- **Paper says:** iterate from round 1 until a round returns no score above
  T_b. It gives no upper bound.
- **Problem:** a degenerate or very weak cipher never terminates.
- **Choice:** cap at `max_rounds`, defaulting to the cipher's
  `nominal_rounds`. Hitting the cap is flagged.
- **Alternative:** no cap.
- **Impact:** None on paper-scale ciphers. It only guarantees termination.

### A-012 — Independence of per-round runs
- **Paper says:** "we run our optimizer iteratively from round 1 to round R+1".
- **Open:** whether round r+1 starts from round r's population.
- **Choice:** fresh random start each round.
- **Alternative:** warm start.
- **Impact:** Medium. A warm start would make lists correlated across rounds
  and shrink the union.

### A-013 — "Sum" versus mean in the bias score
- **Paper says:** Definitions 1 and 2 say "the sum of the biases", but both
  formulas include 1/n.
- **Choice:** the mean, as in the formulas.
- **Evidence:** the 0.004 random baseline and T_b = 0.01 (§5.4) only make
  sense for the mean. A sum over 32 bits would be about 0.13.
- **Impact:** High if reversed. Determined by internal consistency.

### A-014 — Absolute value in the bias score
- **Paper:** bars around 0.5 − p̂_j, partly lost in my rendering.
- **Choice:** absolute value.
- **Evidence:** signed deviations would average to about 0 and could not
  produce the 0.004 baseline.
- **Impact:** High if reversed. Determined.

### A-015 — How samples are drawn
- **Determined:** each sample has its own key K_i (Def. 2).
- **Open:** whether samples are drawn freshly per evaluation or shared across
  candidates in a generation (common random numbers); the distribution of X and
  K; and whether the initial population uses the same t.
- **Choice:**
  - X and K uniform and independent;
  - fresh draws for each evaluation;
  - the same t everywhere.
- **Alternative:** common random numbers within a generation, which reduces
  ranking noise among near-equal candidates.
- **Impact:** Low to Medium on ranking among close candidates.

### A-016 — Rescoring the union
- **Paper says:** "rerun the scoring procedure for the union … to obtain, for
  each difference δ_i, R bias scores".
- **Choice:** fresh samples, the same t, every r in 1..R (including rounds
  where δ_i was already scored).
- **Alternative:** reuse search-time scores where they exist.
- **Impact:** Low.

### A-017 — Final-score weighting (RESOLVED BY INSPECTION)
- **Paper says (§5.2):** S_δi = Σ_{r=1}^{R} ( b̃_{i,r} ). The same sentence
  calls it "a weighted score … providing higher weight to later rounds while
  considering lower round scores". The paragraph argues that a simple sum may
  favour less interesting differences. The authors describe the choice as
  "certainly not optimal".
- **Verified by inspection:** the operator rendered the equation directly.
  The parentheses contain the bias score b̃_{i,r} and nothing else. There is no
  multiplier and no weight symbol. No glyph was lost (S-2 item 4 is refuted).
- **Resolution:** the contradiction is in the paper itself, not an artefact of
  text extraction.
  - The only equation given is an unweighted sum.
  - The prose describes a weighted score that increases with round.
  - No weight values are stated anywhere.
  - The paper cannot fully specify the final ranking.
- **Choice:** default w_r = r. **NOT IN PAPER, permanently.** This is II-2's
  own construction, chosen as the simplest weighting that satisfies the prose.
  It cannot be traced to the paper.
- **Also reported:** the uniform sum, which is the printed equation, is always
  reported and can be selected with `round_weighting="uniform"`.
- **Alternatives:**
  - w_r = 1 (the printed equation);
  - any other increasing weighting, such as 2^r.
- **Impact:** High.
  - Auditor-measured: on a synthetic cipher with a round-dependent bias
    gradient, linear versus uniform changed the top-ranked difference in
    8 of 12 seeds, and the full ranking in 12 of 12.
- **Finding:**
  - The paper's final-score step is internally inconsistent.
  - The ranking it produces depends on which reading an implementer adopts.
  - Any II-4 comparison should state which weighting each arm used, and should
    report results under both.

### A-018 — Union order and final ties
- **Paper:** silent.
- **Choice:** order by first appearance (round, then rank), and use a stable
  sort by S.
- **Impact:** Low. It matters only for exact ties.

### A-019 — Tie-breaking inside Algorithm 1
- **Paper:** silent.
- **Problem:** scores are multiples of 1/(t·n_out), so ties occur.
- **Choice:** stable sort, so ties keep generation order.
- **Alternative:** random tie-breaking.
- **Impact:** Low.

### A-020 — Input width versus output width
- **Paper says:** Def. 2 assumes E: F₂ⁿ × F₂ᵏ → F₂ⁿ, so the same n is used for
  both. Some analysed primitives are permutations (GIMLI, k = 0).
- **Choice:** separate `input_bits` and `output_bits` in the interface, and
  normalize by `output_bits`.
- **Impact:** None for block ciphers. It avoids silently wrong normalization
  elsewhere.

### A-021 — Where the difference is injected
- **Paper:** Algorithm 1 does not say where δ is injected. Related-key results
  exist (HIGHT, TEA; §7) but the split of δ between plaintext and key is not
  specified. Modular-addition differences appear only for [BR21].
- **Choice:** XOR into the plaintext only, the single-key setting. The other
  settings are out of scope.
- **Impact:** None within scope. Related-key runs would need a design choice
  the paper does not give.

### A-022 — What a "round" is
- **Paper:** Table 1 footnote *2 counts TEA/XTEA in cycles of two rounds, so
  the round unit varies by cipher.
- **Choice:** the cipher interface defines its own rounds. The audit adapter
  must use the unit it intends to compare.
- **Impact:** High for cross-checking R. None on the algorithm itself.

### A-023 — Populations smaller than 2 or 32
- **Paper:** silent. This never happens at the paper's scales.
- **Choice:**
  - proceed with what remains;
  - if fewer than 2 members remain, end the run early and record the
    generation count;
  - Δ_r may have fewer than 32 members.
- **Impact:** Low. Matters only for toy n.

### A-023 — addendum
- If no children survive hygiene and elitism is off, the run stops early.
- Δ_r is then the current population: the last selection made, with its scores.

### A-024 — Initial population after filtering
- **Paper says:** "1024 times".
- **Open:** whether the 1024 is counted before or after removing zeros and
  duplicates.
- **Choice:** before. There is no top-up.
- **Alternative:** top up to 1024 distinct nonzero values.
- **Impact:** Negligible for n ≥ 16.

### A-025 — Contract keys `generations_completed` and `evaluations`
- **Paper:** defines neither.
- **Choice:**
  - generations are totals across all Algorithm 1 runs, including the
    terminating run at round R+1;
  - an evaluation is one call to b̃ (one difference at one round);
  - `encryptions = 2·t·evaluations` is reported separately.
- **Impact:** None on search. Matters only when comparing the two arms.

### A-026 — Bit order and integer representation
- **Paper:** writes differences as hex integers, sometimes as word tuples
  (§5.1: "(0x0040, 0x0000)").
- **Choice:**
  - integers map to bit arrays with the most significant bit first;
  - the mapping from a word tuple to an integer (concatenation order,
    endianness) is left to the audit's cipher adapter.
- **Impact:** None on the score, which is symmetric across bits, or on the
  mutation distribution. High on whether returned integers compare correctly
  across the two arms.

### A-027 — ε-close (§5.3), not implemented
- **Paper says:** the text says "within ε of each other". The Table 3 caption
  says "differ at most by a factor ε to the optimal score". The prose example
  says "within 10% of the optimal".
- **Open:** absolute or relative, and relative to what.
- **Choice:** not part of Algorithm 1, so not implemented. Logged as a paper
  ambiguity.
- **Impact:** None here.

### A-028 — Injectable scorer
- **Context:** the brief requires injectability only if neural training is
  involved. Algorithm 1 uses the bias score, which needs no neural network.
- **Choice:** b̃ can still be replaced via a `scorer` argument, for tests only.
  The default is Definition 2.
- **Impact:** None.

### A-029 — Typographical anomalies not used
- **Paper says:** Definition 1's denominator is 2^{n+k} while the key set is
  written F₂^{k−1}. §2.1 normalizes a probability by |P| + |K| rather than
  |P|·|K|.
- **Choice:** neither enters the implementation, since only Def. 2 is computed.
- **Impact:** None. Recorded as a reproducibility observation.

### A-030 — Rounds are not an input of Algorithm 1
- **Paper:** the pseudocode never mentions r. The round count enters only
  through b̃ and the §5.2 loop.
- **Choice:** EVOLVE takes r explicitly. Single-round mode exposes it.
- **Impact:** None. This is a clarification.

### A-031 — Algorithm, figure and section numbers may not be stable across revisions
- **Given PDF:** the evolutionary optimizer is Algorithm 1 in §5.2; Gohr's
  optimizer is Algorithm 2 in Appendix A. The bias score is in §5.1. There are

- **Downgraded:** the reversed numbering and §5.1 placement attributed to the
  canonical revision came from an automated extraction of the same kind that
  invented the A-017 sentence. Unverified until the operator checks the PDF
  directly.
- **Withdrawn:** the earlier claim that the two revisions differ in content.
  It rested only on the invented sentence. The operator-verified §5.2 text

- **Still open:** which revision the given PDF is. The audit can settle it by
  comparing page and figure counts.
- **Consequences:**
  - All II-2 citations are relative to the given PDF. Mapping them to the bound
    revision needs a concordance.
- **Impact:** Medium for the audit's bookkeeping. None on the code.
