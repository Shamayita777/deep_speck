## What the frozen topology note permits, and what this implements

The frozen `TRAINING_TOPOLOGY` (`audit/implementation/preflight.py`) says:

- Arms and blocks run sequentially on one device.
- A distribution strategy is out of scope, because it would change the per-replica batch and the gradient semantics.
- Two separate blocks may run as two independent processes, one pinned to each GPU with `CUDA_VISIBLE_DEVICES`, "because blocks are independent experimental units". This was not built, because two processes would share one run directory and one state file.

This amendment implements exactly that permitted form:

| frozen semantics | how they are kept |
|---|---|
| one device per fit, no distribution strategy | each worker is a separate process started with `CUDA_VISIBLE_DEVICES=<g>`; nothing is distributed |
| both arms of a block trained in turn | a worker trains both arms of its block in the frozen order, with the frozen `_build_and_verify_arms` and `_train_arm` |
| blocks are independent units | two workers train two different blocks concurrently; a block is claimed by exclusive-create file per session |
| one run directory, one state file | workers write only `blocks/<id>/…` and `blocks/<id>/training_state.json`; the parent is the only writer of `state.json` and `firewall.json` |
| sealed test set generated once, sealed under every block id | done by the parent with the frozen `_sealed_test_set` before any training |
| block data generated once and never regenerated | generated by the parent with the frozen adapter call before training, recorded in `state.json`, and checked by every worker |
| evaluation, firewall consumption, replacement, analysis | the frozen `ComparisonRunner.run()`, called unchanged after the merge; it finds every arm TRAINED and only evaluates |

Unchanged:
- seven blocks, two replacement blocks and the replacement rule;
- both arms and their identities;
- seeds `800000 + 2·block + arm`;
- 200 epochs;
- the data procedure, the shared sealed test set and terminal-epoch evaluation;
- pairing, α = 0.05, δ = 0.01 and every decision rule.

Replacement blocks, if needed, are trained by the frozen `run()` in the parent, serially. This is slower, not different.

## Separation of evidence

- The amended source files enter the experiment fingerprint.
- The frozen runner refuses to resume an amended run directory, and the amended runner refuses a frozen one. Both directions are tested.
- The default output is `audit/implementation/runs/ii-4-gohr-impl-v1-par1`.
- Evidence from the two runners is never pooled.

## Environment

The frozen gate passes only under the recorded stack:
- Python 3.13
- TensorFlow 2.20.0
- Keras 3.13.2
- numpy 2.1.3
- scipy 1.16.3

Two version effects, both measured:
- **Python 3.11 or 3.12:** the V6 semantic digest of `audit/common/outcomes.py` is an AST dump that differs between Python versions, so the frozen gate fails.
- **Keras 3.15:** the frozen architecture check refuses, because Keras 3.15 serialises the Conv1D initialiser with two extra fields.

## Runtime (projected; replace with the Kaggle pilot's per-epoch time)

Both arms of a block train one after the other on one worker, so the scheduling unit is the paired block, not the arm.

| item | basis | hours |
|---|---|---|
| one arm, 200 epochs | measured on T4, frozen `DESIGN_RATIONALE.compute_estimate` | 3.7–4.6 |
| one paired block | 2 arms in sequence | 7.4–9.2 |
| parent, before training: sealed set and 7 block datasets on CPU | estimate | ≤ 0.5 |
| busier worker: 4 of the 7 blocks (claimed dynamically, so either GPU) | 4 blocks | 29.6–36.8 |
| other worker: 3 blocks, then idle | 3 blocks | 22.2–27.6 |
| evaluation, firewall and analysis in the parent | estimate | < 0.3 |
| planned makespan | | about 30.4–37.6 |
| each replacement block (frozen `run()`, serially, after evaluation) | 1 block | +7.4–9.2 |
| worst case, both replacements used | | about 45–56 |
| total GPU work (unchanged by parallelism) | 14 arms (+4) | 51.8–64.4 (+14.8–18.4) |

**Per Kaggle session overhead (estimate), about 0.5 h:**
- environment install;
- the readiness gate (frozen suites plus the amendment suite, roughly 10 min);
- archive restore and creation.

An interruption loses at most the epoch in progress on each active arm, about 1 minute at production scale.

**Sessions:** with an 11 h budget per session and about 10.5 h of training in it:
- planned run: 3 to 4 sessions;
- worst case: 5 to 6 sessions.

## Not established here

- Real CUDA device placement, GPU throughput and GPU nondeterminism. The two-GPU Kaggle smoke and pilot establish these.
- The four frozen `test_preflight_filesystem` tests that fail on macOS, because they probe Linux mount information. They must pass on the Kaggle host, or the frozen gate refuses.
